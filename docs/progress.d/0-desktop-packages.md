- 2026-11-27: Missing packages on the desktop (B13). Until now the desktop's builds left downloads to retex's own settings, whose default downloads without a terminal: the user was never asked and could not turn them off in TeXCraft. Now Settings › Building › Missing packages (desktop only; `build.missing_packages` with `ask`, `auto`, `manual`, `off`) decides: the build worker starts with retex's `Downloads::Always` for Download automatically and `Never` otherwise (restarted when the setting changes), so packages come from TeX Live's own repository of the installed year (tlnet through `mirrors.ctan.org`, or a past year's `tlnet-final`), never from the browser's package server, and match the installed TeX Live. The formulas' worker never downloads. A build's errors that lacked a TeX Live package (`package `x` not found`, with retex's `x.sty is in the TeX Live package `y``) or TeX Live itself are listed in the outcome (`missingPackages` in `build.result`), their help is TeXCraft's per setting (retex's advice about `retex config` and `RETEX_OFFLINE` goes; its install command for the system stays), and a build after a download notes the package downloaded. With the setting on Ask the window asks once a session, naming the package: Download Automatically (builds again at once, the status line saying it downloads), Install Them Myself, Don't Download, Open Settings, Not Now; the CLI never asks and prints what was missing and how to change the setting. Left: accessible PDFs, exports and the CLI run retex in process, where retex 2.5 neither downloads nor finds downloaded packages (their message says so).
