- C8, the browser: projects of the browser's library keep a history too. Each save that changes a project records a version ("Saved with TeXCraft", by the review name, else TeXCraft); a save that changes nothing records none. `texcraft_history::store` keeps the versions as values: each file's bytes once, under its git blob id (SHA-1 of `blob <length>\0<bytes>`, through `gix-hash`, which also builds for wasm32), each version its parent, time, author, message and files (paths and blob ids), its id the SHA-1 of that manifest. The library keeps a project's history with it (`Stored::history`); a save tells the shell only what is new (`Change::Versions`: the version and the bytes the history did not have), a rename moves the whole history and a delete removes it. The web shell keeps versions and bytes in their own IndexedDB stores (`versions`, `blobs`, by `<project>/<id>`; database version 3, older databases open with empty histories) and loads them at start. `history.status/list/show/diff/restore` read it as on the desktop, so the History panel works unchanged; `history.commit` is refused there (saving already makes the versions). Limits: versions are not git commits yet (no tree or commit objects; the blob ids are git's, so C5 can write them); the whole history is loaded into memory at start, and nothing is ever pruned.
