- 2026-11-27: New Project on a forge (docs/design/new-project.md; C11). After the template, **Create Project…** goes on to a second step in the same dialog, **Where to Keep It**: Import's cards for This Computer (a folder) or This Browser, each connection that can make repositories (gitlab.com, github.com, servers added; its line says who is connected and Default) and **Add a Connection…**, which opens the connection dialog and comes back with the new card chosen. The default connection is chosen, else the last place (`new_project_place` in the preferences), else this computer. One line says to start on Overleaf by making the project there and importing it. A forge's card asks for the repository's name (from the template's title, checked on the forge half a second after typing: free, or taken), the owner (`forge.owners`), who can see it (Private by default, Internal on GitLab, Public) and on the desktop the folder. **Create Project** makes the repository first (a taken name or missing permission ends it there, said in the dialog, nothing written), then writes the template, commits it, sets `origin` and pushes (the browser: the template is the repository's first commit and the project is linked), the footer saying each phase; then the project opens and the status says "Created ada/article on GitLab.". A push that fails keeps the project and the repository, says why, and offers Try Again. Commands: `project.from_template` takes `forge` (operation `new_project`), `forge.name_available`; `forge.create_repository` takes `visibility`. Tests: the forge's `exists`, the engine's `new_project.rs` (GitLab made, written, pushed and Sync at once; a name taken stops before any file; a push failure keeps the project; the browser's first commit; internal refused on GitHub) and the window's `new_project.rs` (the places and the default, made on a fake GitLab and GitHub, a name taken, a push failure with Try Again, a connection added from the step, both steps by keyboard, a phone's list).
