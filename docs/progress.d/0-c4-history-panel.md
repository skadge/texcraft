- History panel (C4): a History section in the side panel (rail button, `view.side.history`) lists the project's versions newest first, each with its message, when (relative: "5 minutes ago", "yesterday", a date past a month), who, and how many files it changed. Choosing a version lists its files with the word for each change (added, modified, deleted); choosing a file compares it with the version before, read-only, line by line with + and − marks and line numbers as well as colour (new engine command `history.diff`, through the `similar` crate). "Restore This File…" and "Restore the Project at This Version…" go through `history.restore` after a confirmation that says the result is unsaved changes and the next save makes a new version; a file a version deleted comes back as it was before. In a repository the user made, "Commit…" asks for a message and runs `history.commit`. Without a history (an untitled project, a folder before its first save, the browser) the panel says why. The list follows the repository's latest commit, so it is read again after every save and commit.
- `history.commit` in a repository the user made refuses while changes are staged in git ("Some changes are staged in git: commit them with git first"): its commit rewrote the index from the new tree and unstaged them.
