- 2026-11-27: **TeX packages built in** (W14, for the release after retex 2.6.0 is on crates.io). **Desktop**: `texcraft` and `texcraft-cli` carry retex's bundle `core` (retex's feature `bundled`, the crate retex-data 2026.0.0: 64 TeX Live 2026 packages, the archive `retex-core-2026.tar.xz` of 9.7 MB), through new `bundled` features of texcraft-compile and texcraft-engine that only the desktop apps enable. retex unpacks it once into its cache (`<cache>/retex/bundle/`, 52 MB) and searches it after an installed TeX Live of the same year; a TeX Live 2025 is used on its own; what neither has is downloaded as before. Measured with a release build in a sandbox with no TeX Live (the system's TeX folders hidden), no network and a new cache: the letter and CV templates build; the first build ever took 8 to 26 s on a loaded machine (unpacking about 2 s, then the format), later ones under a second. The other built-in templates need a package the bundle lacks (booktabs for the article, the thesis and the example; enumitem for the homework sheet; beamer for the slides) and build once it is downloaded. The binaries grow by the archive: `texcraft` 101.4 to 111.1 MB, `texcraft-cli` 56.1 to 65.8 MB. **Browser**: `cargo xtask tree-site OUT --bundle[=ARCHIVE]` builds the TeX tree on the bundle (retex-data's archive, found through `cargo metadata`, or a file), whole, with its `texmf.cnf` and generated files and its year in `seed/version.txt`; the packages of `tree.txt` the bundle lacks still come from the installation (of the same year), and a package folder the bundle has comes from the bundle alone. `--no-installation` needs no TeX Live at all: the recordings run over the bundle alone (`RETEX_BUNDLE`, an empty `TEXMFCNF`), and the seed's format and blank project build over it. The bundle's `MANIFEST.toml`, licences and GPL sources go to `tree/retex-core-2026/`. The seed's runs set `RETEX_BUNDLE=none`, so a native retex with a bundle of its own reads only the tree. The output layout is unchanged, and so is the worker. Without `--bundle`, the tree is made as before. **The trees compared**: 0.21.0's site (CI, TeX Live 2026 image) has 9384 files, 191.4 MB; the bundle alone 3025 files, 43.6 MB; the bundle with `tree.txt`'s additions (a local TeX Live 2026) 9230 files, 169.2 MB, of which the bundle's 3025, whose versions win (`latex.ltx` is the bundle's). The current tree's files the bundle lacks are 6739 (149.8 MB) in 335 TeX Live packages (the largest: mlmodern, Latin Modern's Type 1 and TFM files, newtx, noto-emoji, circuitikz, libertine, tex-gyre, pgfplots), every one of them in the package server's snapshot `2026/20261126`. CI keeps building the tree as before until a CI change of its own switches it to `--bundle` (with `tree.txt` kept: a lazily fetched file costs only hosting, while a download fetches a package's whole archive from one server, after its 3 MB package list, and the publishers' templates and beamer would each need some).
