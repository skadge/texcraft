- C5, step 1 (docs/forges.md): projects from GitLab with a personal access token. `texcraft-forge` is GitLab's REST API as plain async Rust over a transport (ureq on the desktop, on its own thread; `fetch` in the browser; an in-memory GitLab in tests): a project's address in any form users paste (HTTPS only, but for `localhost`), the default branch, the branch's head, the recursive tree page after page (`Link` or `X-Next-Page`), the files' blobs eight at a time checked against their git blob ids, changes found by blob id (a rename is a move), one commit with `create`/`update`/`delete`/`move` actions, and errors in words (401, 403 with the scopes needed, 404, 429 with `Retry-After`). Files over 10 MB are skipped and said, projects over 200 MB refused; hidden files, symbolic links and submodules stay on the branch. Commands: `forge.open {url, token, ref?, background?}` (the desktop opens the project in memory, linked to its branch and in no folder; the browser keeps it in the library with its link), `forge.status` (base, branch, changed files), `forge.commit {message, token?, background?}`: a protected branch is refused before anything is sent; a branch that moved since the base is compared with it, and its commits to other files are kept and taken into the project, while commits to the same files refuse the commit, naming them (the three-way merge is step 2); a commit someone made meanwhile is found by the new commit's parent and taken in. With `background` the commands return at once and `Session::poll_forge` gives the outcome. Tokens are kept for the session only, per instance, never in the library, preferences, logs or results. Interface: Open from GitLab… on the start page and in File (address, branch, token with its scopes explained and a note that it is not kept), the project and branch with the number of changed files in the top bar, File › Commit to GitLab… (the changed files, a message, the token again when the session has none), outcomes on the status line. Limits: the token is asked again after a restart or reload; review threads are not carried to or from the branch; files are fetched one blob each (no archive); on the desktop the link lasts while TeXCraft runs (Save Project As copies the project into a folder, which opens unlinked later).
