- 2026-11-26: Merging word by word (C12 step 1). `texcraft_forge::merge::merge3`, which Sync, Pull, the forges' update and commit (REST projects) and the browser's take-in of an update all use, merges a chunk of lines both sides changed differently again token by token: words, runs of whitespace, line endings, punctuation, and LaTeX's control sequences, control symbols (`\%`), braces, `$` and `%` comments each whole, so markup is never split. The tokens are diffed base→mine and base→theirs with a Myers diff of the crate's own, bounded at 1000 token edits a side (O((n+m)·D) time, O(D²) memory, its matching checked before use) and at 200 kB a side; past either the chunk stays a conflict. The chunks are put together with the same diff3 logic as the lines (now one generic function); the same change on both sides counts once, theirs' line endings become the local one. Changes to neighbouring lines now merge (git makes them a conflict). `merge::merge_text` returns `Merge::{Clean, Conflicts(Vec<Passage>), NotText}`, a passage holding its byte ranges in base, mine and theirs and the text of each, for the passage-by-passage view of step 2 (no interface yet). Nothing in the module knows TeXCraft; it should move to storytold/craft-libs in a PR of its own. Tests: different sentences and words of one line, the same word changed differently (one passage, narrower than the line), a `\cite` added beside a typo fixed, an edit inside `$…$` beside prose, identical edits, a sentence deleted beside another edited, CRLF with an LF side, non-UTF-8, 400 random paragraphs edited in separate word ranges (a fixed-seed LCG: always merged, into both edits once), hostile inputs (a line over the limit, 60 000 tokens all changed, unbalanced braces, lone `\r`, a trailing `\`, empty files); the diff against the textbook LCS table; an engine Sync over the in-memory git server merging two sentences of one paragraph and sending without asking. Limit: a word repeated next to an edit ("the the") can make the edit's place ambiguous, a conflict.
