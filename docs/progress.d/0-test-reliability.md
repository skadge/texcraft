- 2026-11-26: Reliable UI tests. The kittests that failed now and then under load (`unsaved::*`, `frame::help_user_guide…`, `frame::the_help_menu_opens_the_retex_manual…`, `frame::the_app_icon…`, `gallery::searching…`) all had one cause: their window had the default settings, so the project compiled once it had been open for the auto-compile delay, which a few test frames reach (a quarter second each). The build runs on a thread, and its spinner asks for frame after frame until the thread ends, so `Harness::run` gave up when the thread was late. Shown by a build that takes 200 ms: exactly those seven tests fail every time, and none does after the fix. They now open their window through one shared constructor (`tests/it/support.rs`) that does not compile by itself; the tests of building still compile. Ruled out: background grammar (its `request_repaint_after` is listed among the repaint causes but is not an immediate repaint; the suite passes with Harper delayed by 30 ms or 300 ms per passage) and the interface language (it is per thread, `thread_local!` in `i18n.rs`, so a test switching it does not reach the others).
