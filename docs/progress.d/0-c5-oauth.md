- 2026-11-25: C5 step 4 (docs/forges.md): signing in to GitLab and GitHub instead of pasting a personal access token. Sign In with GitLab (the Open and Commit dialogs first, the token behind "Use a personal access token instead"; Settings › Accounts) runs OAuth 2's authorization code with PKCE as TeXCraft's non-confidential gitlab.com application: on the desktop a loopback listener on `127.0.0.1:47321/callback` takes the one redirect while the system's browser shows GitLab's page; in the browser the whole page goes to GitLab and comes back to its own address, the state and verifier waiting in the tab's session storage, the code taken out of the address bar and exchanged (`forge.sign_in_return`). It asks for `read_api read_user`; a commit with a read-only sign-in is refused before anything is sent and the dialog offers Allow Commits on GitLab (`api`). Expired access tokens are renewed with the refresh token before an operation, the rotated refresh token kept whatever the outcome. Sign In with GitHub (desktop) uses the device flow: the code shown with Copy Code and GitHub's page opened, polling at GitHub's interval and slower on `slow_down`, ending in words on `expired_token` and `access_denied`; in the browser GitHub keeps the token, and the dialog says why. Sign-ins are kept in the system's keychain on the desktop (a restart stays signed in), in the tab's session storage in the browser (chosen over IndexedDB so a long-lived refresh token does not outlive the tab), never in preferences, the library, logs or results. Sign Out revokes on GitLab (`/oauth/revoke`) and forgets; GitHub's cannot be revoked by an application without a server, which is said. Who is signed in (`/user`) shows in the dialogs and Settings. Client ids: `GITLAB_CLIENT_ID` and `GITHUB_CLIENT_ID` in `crates/forge/src/oauth.rs`; an id ending in `_PENDING` turns the button off with "This build has no GitLab application yet". Commands: `forge.sign_in {service, write?}`, `forge.sign_in_return`, `forge.cancel_sign_in`, `forge.sign_out {service}`, `forge.accounts`. Tests: PKCE against RFC 7636's vector, the authorize URL, the exchange, refresh, refused refresh and revocation, `/user`, the device flow's pending, slow-down, expired, refused and cancelled states, placeholder ids, tokens never printed (forge, scripted transport); the loopback listener with a local client: the code, ignored requests, a refusal shown escaped, a timeout, a cancel, a port in use; signing in on the desktop then opening with no token and lasting a restart, committing asking for `api` then committing, an expired sign-in renewed and the new refresh token kept, the browser's round trip with its state checked and used once, GitHub's device flow and its code shown and cancelled, signing out revoking (engine); the dialog offering sign-in first, the button off with its reason, and a sign-in from the dialog then opening a project (kittest).
