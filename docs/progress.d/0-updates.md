- 2026-11-26: In-app updates (A8). **Checking**: `texcraft_engine::update` reads GitLab's latest release (`/projects/severin-lemaignan%2Ftexcraft/releases/permalink/latest`: tag, notes, asset links on gitlab.com only) and, when gitlab.com cannot be reached or fails, the GitHub mirror's (`/repos/skadge/texcraft/releases/latest`, read with craft-update's `parse_github_release`, its download links and `digest` checksums), through the session's transport (the desktop's HTTPS client, the browser's `fetch`, a fake in tests), with nothing about the user in the request. Versions compare with craft-update's rules (`offers_update`: a build from source between releases is offered only a higher release); `TEXCRAFT_PRETEND_VERSION` sets the running version, to try an update. Commands: `app.check_updates` (`{"automatic": true}` asks nothing when Settings › Appearance › Check for updates is off or the last answer is less than a day old), `app.update_status` (running version, install, setting, last check, the latest release with its notes and this copy's action, progress, error), `app.update_settings {check}`, `app.install_update`; a session checks only once the shell enables it (`Session::enable_updates`), so tests, the CLI and agents' sessions contact nothing. The setting and the last answer's time are kept with the preferences; a failed check is not an answer, so the next start tries again. **Telling**: the window asks 8 s after its start (never during it); a newer release shows "TeXCraft X.Y.Z is available" at the status bar's end (announced), which opens the What's New dialog: the release's notes as text (headings, bullets, emphasis and links of the Markdown taken out), what this copy does, and its buttons; Help › Check for Updates… opens it with a check at once (Checking…, up to date, or why it did not work, with Check Again). **Updating**, by install (`update::plan`, `Install::detect`): an AppImage (`APPIMAGE`) downloads `TeXCraft-X.Y.Z-<arch>.AppImage` beside itself with craft-update's resumable, checksum-checked download, checks it again against its `SHA256SUMS` line (or GitHub's checksum), keeps the old one as `<file>.old` (a hard link, or a copy) and renames the new one over it, so the file is always whole and the running copy keeps working from its mount; a mismatch removes the download and replaces nothing; Restart Now (`app.restart_to_update`) asks about unsaved changes, closes, and the shell starts the new AppImage as it exits (craft-update's `spawn_detached`, without the old runtime's environment); the new one removes the `.old` when it starts. A Flatpak (`FLATPAK_ID`, `/.flatpak-info`) is not replaced: the dialog says updates come through Flatpak, with the software centre and `flatpak install --user` hints and the release page. Windows and macOS (unsigned zips) are not replaced either: the dialog says why and downloads the mirror's `TeXCraft-X.Y.Z-x86_64-windows.zip` or `-aarch64-macos.zip` (Intel Macs and other machines get the release page). A build from source links the release page. The browser compares its version with the site's `version.txt` (written by `cargo xtask version-worker`, Trunk's post-build hook) and offers Reload, unsaved changes saved first or asked about. craft-update's own self-update flow is not used: it needs the suite's asset names (`<id>-<version>-<os>-<arch>`) and GitHub releases, and it keeps no `.old`; reading GitLab's releases belongs in craft-update and moves there in its own change.
