- 2026-11-26: Saving by itself, versions at their moments, and Sync (issues #34, #35, and #23's question). **Saving (C9):** a project with a place (a folder, or a name in the browser) is written about 1.5 s after typing stops, at once when the window loses the focus, and before it closes (`project.write`: the files, no version); the top bar says "All changes saved", "Saving…" or "Not saved" (red, with why on hover and on the status line, announced). A failed write leaves the project dirty and is not retried until it changes; leaving then asks, now in words that say the write failed ("The last changes to … could not be saved / kept in this browser", Try Again, Don't Save / Don't Keep, Cancel); the browser's leave warning follows the same dirty state. Settings › Editor › Save automatically (on by default, `project.autosave`, kept in the preferences) brings the old behaviour back. **Versions:** not on each write: `history.version` makes one after 300 s without typing when something changed (`Session::unversioned`), on closing, before a restore or Accept All Suggestions, before a push, a pull and a Sync, and on File › Save; `automatic` ones are not made in a repository someone else made (C8's "commits only when asked" stays). The History panel's greyed Commit… and its long note are gone; Name This Version… (the tag button) makes a version with a name. **Sync (C5, step 6):** `project.sync` makes a version, fetches and merges (fast-forward, or three-way per text file; files in conflict are listed by `forge.status` and settled with `resolve`, mine or theirs, through `History::merge_choosing`), then pushes, one background operation (`git_busy` "sync"); an empty remote is pushed to. A forge-linked project (the browser's REST path) commits its changes with a message from `describe`, or pulls when it has none. The top bar's ⇅ Sync, for a project with a remote, counts versions to send and to receive (↑2 ↓1, in words in its name and tooltip); its conflicts open the resolve dialog (Sync again with the choices); a missing or refused token (`ForgeProblem::NeedsToken`) opens a token dialog, and a token the server took is kept for the session. Push and Pull in the History panel are framed buttons with arrows (`widgets::framed_button`), with the counts beside them. **Overleaf (#35):** a remote at `git.overleaf.com` is recognised (`git.remotes`' `hosting`), named with our own icon (`assets/icons/online-project.svg`, drawn for TeXCraft) beside Sync and in the History panel, and reached with an Overleaf git token as the password of the user `git`; a user name in an https address now goes to the credentials, not the URL. Lucide's arrow-up, arrow-down and arrow-up-down icons added.
