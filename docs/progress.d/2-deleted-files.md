- Issue #2: a file deleted, renamed or moved in TeXCraft no longer comes back when the project is reopened. The session keeps the paths it opened from or last saved to the project's folder; a save to the same folder removes those the project no longer has (and the folders that leaves empty), never any other file (untracked files, hidden entries, build files). A file the repository's last commit holds as it is on disk is deleted, since the history keeps it; any other goes to the system's trash (`trash` crate), so nothing is lost the user cannot get back. Agents cannot reach the trash outside their roots, so such a file stays for them and the save says so. `project.save` reports what it deleted, trashed or left; the status line says what went to the trash or could not be removed.
