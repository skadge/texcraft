- C5, step 2 (docs/forges.md): keeping up with a GitLab branch. `texcraft_forge::merge::merge3` is a three-way merge of text files line by line (diff3 over the `similar` crate's Myers diff): changes to different lines merge, the same change on both sides is no conflict, overlapping or neighbouring changes and binary files are conflicts, and the merged file keeps the local line endings. `forge.pull {token?, resolve?, background?}` takes in the branch's new commits: files changed only there are taken, files changed on both sides merged; a conflict (overlap, deleted on one side and changed on the other, added twice, binary) takes in nothing and is listed by `forge.status` until settled with `resolve: {path: "mine" | "theirs"}` on a pull or a commit. `forge.commit` catches up the same way before committing on top of the head, and with `new_branch` commits the changes from the base to a new branch (`start_sha`) and opens a merge request (`POST …/merge_requests`), the project then following the new branch; a protected branch or a role that cannot push refuses the commit with nothing sent and offers that way (`cannot_push`). Updates computed while the user kept editing are merged into the edits, or the edits are kept and said. Review threads (`.texcraft/review/*` only) are loaded from the branch into the review, committed and pulled with the project. Interface: File › Update from GitLab; the commit dialog lists files in conflict with Keep mine and Take theirs for each and a "Commit to a new branch and open a merge request" option (the only one for a protected branch), reopens with its message after a refusal, and the merge request's link is shown once opened; the top bar shows files in conflict; the branch is checked quietly every two minutes and when the window gets the focus back, while signed in. Tests against the fake GitLab (now with protected branches, `start_sha` and merge requests): pulls with and without conflicts, both resolutions, the merge request path, review threads round trip, and the merge's unit tests; the window's tests cover the conflict and merge request dialogs and the check on focus. Limits: no OAuth yet (step 3), no conflict markers or hand merge in the editor, choices per file.
