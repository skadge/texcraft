# TeXCraft progress log

What changed, day by day, newest first. Each change adds a fragment `docs/progress.d/<issue>-<branch-slug>.md` instead of editing this file (RFC-0017); fragments are joined here at release time. What is done and what comes next is in [ROADMAP.md](ROADMAP.md).

- 2026-11-24: retex 2.5.0. In the browser, the whole project goes to the engine (under `/project`, started in the main document's folder through `PWD`), so files outside that folder are found, and draft images work (`--draft-images`).
- 2026-11-24: The browser's TeX tree is cut to what LaTeX documents read: ConTeXt's folder file by file, the pdfTeX font map cut to the tree's fonts. 174 MB instead of 234, and a first visit's build in 6 s instead of 18.
- 2026-11-24: The comments beside the text can be hidden (a button on the margin, and View › Show or Hide the Comments Beside the Text), kept in the preferences; the Review panel still lists them (#1).
- 2026-11-24: An image dragged from the project's files onto the source is placed there as `\includegraphics[width=\linewidth]{…}` on a line of its own, its path written from the main document's folder; the image's context menu has Insert in Document, at the caret, and the file list's context menu now opens from the keyboard (Shift+F10 or the Menu key). Both go through `file.insert_image`, which agents can run too. When the main document's preamble does not load graphicx, the status line says so; the preamble is not changed.
- 2026-11-24: The browser build carries its own TeX tree (`cargo xtask tree-site`, ported from retex's site build): the packages of retex's list, the blank project's and every template's, with the indexes a first visit needs, so TeXCraft's site no longer needs retex's.
- 2026-11-24: The project's name in the top bar is edited in place (click it, or Tab to it and press Enter; Enter keeps the name, Escape or leaving the field does not). An untitled project is saved under the name typed: in the browser at once, on the desktop in a new folder of that name, in a folder the user chooses. A saved project is renamed by `project.rename`: in the browser its stored copy, on the desktop its folder (refused when the name is taken or outside the automation roots). The build log's messages can be selected, and each has a button that copies it as `file:line: severity: message`; the messages shown and the raw log can be copied whole.
- 2026-11-24: Browser projects keep their review threads (stored at once in IndexedDB, as the desktop writes each thread file at once), and the browser asks before leaving the page with unsaved changes.
- 2026-11-24: Templates in the browser: the web build carries the catalogue's templates (`cargo xtask templates-site`, checked as the desktop's downloads are), and a template makes a named project in the browser. Templates whose class is not in retex's TeX tree do not build there yet.
- 2026-11-24: The browser build keeps the TeX files it fetched and the engine's format and indexes between visits (Cache Storage, renewed when the tree or the engine changes): a blank project's first build on a later visit takes under a second.
- 2026-11-24: Projects in the browser: saved by name and kept in IndexedDB with the preferences and thumbnails, listed on the start page (open, delete), so a project survives a reload. Templates are not offered there yet: their files come from TeX Live's mirrors, which a web page cannot read.
- 2026-11-24: Builds in the browser: TeXCraft's own build of retex's WebAssembly module (`cargo xtask retex-wasm`, the pinned release) runs in a Web Worker through `texcraft-wasi`, a WASI host in Rust, with the TeX tree of retex's site and its indexes. A first build takes 10 to 16 s (Chrome and Firefox), later ones 0.3 to 0.5 s from the preamble's snapshot. A file the run needs late stops it, and it runs again once the file and its folder are fetched.
- 2026-11-24: retex 2.4.1: OpenType features defined from Lua (`addfeature`) substitute and ligate in builds, as with lualatex.
- 2026-11-24: retex 2.4.0: completion, hover, definitions and fixes go through the language server's typed queries (`Server::completion`, `hover`, `definition`, `code_actions`) instead of JSON requests; documents are still synced, and the lint still arrives, through JSON-RPC notifications.
- 2026-11-23: A second polish pass: the start page's rows end on one edge with a themed placeholder for projects without a PDF, comment lines no longer cross the text, and the README's screenshots show the current app, with the formatted view and comments in review. Builds without craft-fonts (CI) have their bold and italic faces again.
- 2026-11-23: retex 2.3.0: Stop cancels through `BuildHandle::canceller` and keeps the worker and its preamble snapshot; the in-process backend is `Retex::spawn_file`, so both backends are one `BuildHandle`; the preview shows a build's draft PDF (a pass that is not the last) with a "Draft · pass N" badge while the later passes run, and agents see it in `build.result`; SyncTeX sends a click in an included file's last paragraph to that file.
- 2026-11-23: Dialogs polished from screenshots: one frame with room around the content, button rows that no longer float down, a named field in prompts, wider setting descriptions, a gallery as wide as its cards, a centred About, and a review margin whose header fits.
- 2026-11-22: Comments. Select text and choose Edit › Comment (Cmd+Alt+M, or `:comment` in Vim): the thread appears in a margin beside its passage, which is tinted in the author's colour and marked in the gutter. Threads take replies, can be resolved (they fold) and reopened, edited and deleted by their author, filtered (all, open, resolved, mine) and visited with F8 and Shift+F8; a narrow editor shows them in the Review panel of the rail. They are kept in the project as `.texcraft/review/<id>.json`, one file per thread (docs/review-format.md), follow the text as it is edited, and come back on their passage when the project is reopened. Agents use the same `review.*` commands. The first comment asks for the name comments carry and makes a key that tells two people of the same name apart (Settings › Review).
- 2026-11-22: Edits, not texts. The editor sends each change to the session as an edit (`file.edit {path, edits:[{start, end, text}]}`, character offsets, with its origin: typing, undo, redo, a peer, a review, or outside TeXCraft), and the session keeps a log of them that the editor and review anchors follow; `file.write` and Replace All record the smallest edits that make their text. Undo skips a peer's or an outside edit: it takes back only one's own change, and the other's text stays.
- 2026-11-22: The browser build: a `web` build profile (optimised for size, no debug information, one optimisation unit) used by `trunk serve` and `trunk build`; a loading screen with the download's progress (`loader.js`, the one handwritten script, a departure from rule 11 the operator chose) until the editor draws; Add Files opens the browser's file picker, and files dropped on the window (desktop and browser) are added to the project. `file.import` also takes a file's contents in base64.
- 2026-11-22: A shorter menu bar: File, Edit, Insert and Help. View's entries all had their buttons (the layout switch, the rail, the PDF toolbar, the app mark) and Build's are on the Compile button, so both menus went; Format joined Insert, which mirrors the editor's toolbar; Show in PDF and Settings moved to Edit. Every command keeps its shortcut and its place in Keyboard Shortcuts.
- 2026-11-22: A formatted view of .tex files, read-only for now: the Source/Formatted switch above the editor shows the file as a document, with headings, styled text, lists, figure cards with their images, chips for references and citations, and formulas as their source. Double-click any part to edit its source there.
- 2026-11-22: The formatted view's model: headings, styled text, lists, formulas, references, citations, footnotes, links and figure cards, each mapped to the source it stands for, with typographic quotes and dashes; anything else stays visible as its source.
- 2026-11-22: A tolerant LaTeX syntax tree for the coming formatted view: commands with their arguments, groups, environments, formulas, verbatim, comments and paragraphs, with every span mapped to the source, and half-typed or unbalanced input marked instead of rejected.
- 2026-11-22: Build options. Settings › Building chooses the engine (from the document, LuaLaTeX or pdfLaTeX) and turns on stopping at the first error and draft images, also in the Compile button's menu; a change rebuilds. Delete Build Files clears the build folder and the worker's snapshots. Agents get `build.options` and `build.clean`.
- 2026-11-22: retex 2.2.0. Quick fixes of build messages carry retex's own titles ("Use \textbf"); the language server learns of TeXCraft's builds directly; images in the editor pane decode through retex-image, JPEG included; `.bib` files get retex's bibliography hints.
- 2026-11-22: The desktop window has no empty system title bar: minimize, maximize and close sit at the right of the top bar (Lucide icons), the bar moves the window and a double-click on it maximizes or restores it, and the edges resize it. Settings › Appearance › System title bar brings the system's frame back.
- 2026-11-22: Faster rebuilds. The desktop app builds through retex's worker, which keeps the preamble between builds: on a document with a heavy preamble a rebuild after an edit takes under a second instead of about five. A line reached from the PDF, the log or the outline flashes in the editor. `packaging/linux/install.sh --dev` gives `cargo run` windows their icon in GNOME.
- 2026-11-22: Source and PDF navigation. A double-click or Ctrl+click in the PDF opens the line that made it; View › Show in PDF (Cmd+Alt+J) marks the caret's line in the PDF. Agents get the same with `pdf.source` and `pdf.locate`.
- 2026-11-22: retex 2.1.0. Builds report their progress (the page being built, the pass), can be stopped, and give the language server their symbols, so completion and hover know the document's commands, environments and citations. Build errors are underlined on their exact span, with retex's own fixes. The SyncTeX data is kept for source and PDF navigation.
- 2026-11-22: retex-lsp in the editor. The language server runs inside the engine and the editor offers completions as you type (labels in references now; commands, environments and citations once builds give it retex 2.1.0's symbols). Agents can ask for completions, hover, definitions and the lint's hints.
- 2026-11-22: Find and replace. An Edit menu (Undo, Redo, Select All, Find, Replace, Go to Line) and a find bar with match case, regular expressions, whole words and in-selection; Replace All is one undoable step. Agents get `file.find` and `file.replace` with the same matching.
- 2026-11-22: TeXCraft's own source editor. The text is a rope with grouped undo (texcraft-buffer), laid out a line at a time, with the gutter, selection, IME and an accessible text node. Vim key bindings (texcraft-vim) can be chosen in Settings: modes, motions, operators, text objects including LaTeX environments and inline math, search, :s, registers, marks, macros; the mode shows in the status bar.
- 2026-11-22: Publishers' templates. New Project opens a gallery of 15 templates (Elsevier, IEEE, ACM, APS, AAS, MNRAS, Nature, ACS, APA, ASME, moderncv, Europass, tikzposter) with search, categories, source and licence. A template is downloaded from TeX Live the first time it is used, checked against TeX Live's signed package database, and kept for offline use; agents use kept templates only.
- 2026-11-22: Scaffold. The workspace is laid out in layers (project, latex, compile, preview, engine, ui-egui, mcp) with a desktop app, a CLI and a web app. retex builds the project in process, and craft-pdf draws the preview. The editor highlights LaTeX, the build log jumps to lines, and the agent tools are confined to their roots.
