Keyboard and accessibility

Everything in TeXCraft can be done from the keyboard. Every command has an entry you can bind to a key, Ctrl+Shift+P finds any command by name, and F6 moves between the parts of the window.

The menus and All Commands

The menus keep what is used often; what is used less is a level down, in a submenu. Every command, in the menus or not, is in Edit › All Commands… (Ctrl+Shift+P): type part of its name, move with Up and Down, and press Enter to run it. Each command is listed with the part of TeXCraft it belongs to and its shortcut; one that cannot run now is dimmed and says why.

  • File: New Project, New Project from Template…, Open Project Folder…, Open Recent, Open from GitLab or GitHub…; Save (Keep in This Browser in the browser), Save Project As…, Download Project as Zip (in the browser), Save PDF As… (Download PDF in the browser); Add to Project (New File…, New Folder…, Add Files…, Import a Zip File…); then, for a project opened from GitLab or GitHub, Commit and Update, or else Save Project to GitLab or GitHub.
  • Edit: Undo, Redo; Cut, Copy, Paste, Select All; Find, Replace, Find in Project, Go To (Go to File…, Go to Line…, Show in PDF); Spelling and Grammar, Review (comments and suggestions), Folding, and Rewrite with AI when a model is connected; All Commands…, Settings….
  • Insert: Heading, Text Style, List; Figure, Table, Formula, Symbols…; Cross-Reference, Citation, Link, Footnote; and Make with AI… and Add a Reference with AI… when a model is connected.
  • Help: User Guide, Keyboard Shortcuts, retex User Manual; Open the Example Project…, First Steps; About TeXCraft.

Compiling and its options are on the Compile button, the layouts, the side panels and the zoom on their own buttons; their commands are in All Commands too. On macOS the same menus are in the menu bar at the top of the screen, with About and Settings in the TeXCraft menu.

Changing shortcuts

Help › Keyboard Shortcuts (also the Keyboard Shortcuts button at the bottom of the rail, and Change Shortcuts… in Settings › Keyboard) lists every command with its shortcut. Give a command a new key, or take one away. Your changes are kept with your settings.

Keys of the editor

These belong to the source editor and are not in the shortcuts list:

  • Ctrl+Space: completions at the caret. F12: go to the definition.
  • Alt+click: add or remove a caret. Ctrl+D: select the word, then add the next occurrence. Escape: back to one caret.
  • Shift+F10 or the Menu key: the text's menu.
  • Tab: take the next words the AI suggests, when shown.
  • Escape (standard bindings): leave the editor, so Tab moves on to the next control.

In Vim mode, Vim's keys apply, and Vim keeps its own Ctrl keys; the window's other shortcuts still work.

Many commands have no default shortcut, such as Section, Numbered Equation, Accept All Suggestions or the layouts (Editor and PDF, Editor Only, PDF Only); you can give them one.

Moving around the window

F6 moves the keyboard to the next region of the window and Shift+F6 to the previous one, from anywhere, including from inside the editor:

  1. Menu bar and project
  2. Sections (the rail)
  3. Project files and outline (the side panel)
  4. Editor
  5. Comments (the margin)
  6. PDF and build log

Within a region, Tab and Shift+Tab move between controls in reading order, and the arrow keys move within lists, trees and menus. A menu opened from the keyboard starts on its first entry. Dialogs take the keyboard when they open, Escape closes them, and the keyboard goes back where it was.

F10, or Alt pressed and released alone, goes to the menu bar. On macOS, where the menus are in the system's menu bar, use Control+F2.

The comments in the margin are reached with F6, not Tab, because the editor keeps Tab for indenting.

Screen readers

  • Every control has a name that starts with its visible label, its role and its state. The source editor and the formatted view are editable text areas with their text, caret and selection.
  • Build results, and other changes away from the keyboard's place, are announced.
  • Colour is never the only sign: errors and warnings have their words and icons, and suggestions are struck through or underlined.
  • The light and dark themes are checked for contrast on every pair of colours. The theme can follow your system's (Settings › Appearance).
  • For readers of your documents, TeXCraft can make accessible PDFs (PDF/UA) and list what keeps them from being read.

Not yet: a full pass with a screen reader by a person; the Keyboard Shortcuts table has one item that does not say its role yet. Reports from screen-reader users are very welcome.
