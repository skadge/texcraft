Projects, files and history

A project is a set of files: a main document, the files it includes, its images and bibliographies. On the desktop it is a folder on your disk; in the browser, it is kept in the browser. Either way it has a history of its versions.

Projects

Opening
File › Open Project Folder… (Ctrl+O) opens a folder Desktop only; recent projects are under Open Recent at the end of the File menu, in the project menu beside the project's name, and on the start page. On the desktop you can also give a folder when starting TeXCraft: texcraft path/to/project.
Saving
File › Save (Ctrl+S) saves every changed file. File › Save Project As… (Ctrl+Shift+S) copies the project to another folder, or in the browser saves it under another name. A dot after the project's name in the top bar means unsaved changes; TeXCraft asks before they could be lost.
Renaming
Click the project's name in the top bar and type. On the desktop this renames the project's folder; an untitled project is saved under the name you type.
The main document
The file that is built, marked in the file tree. Choose another .tex file with Set as Main Document in its menu.

Files and folders

The Project Files section of the side panel lists the project's files and folders. Click a file to open it in a tab; images are shown in the editor's place. File › Close File (Ctrl+W) closes the tab.

  • File › New File… and File › New Folder… ask for a path in the project, such as chapters/intro.tex.
  • A file's menu (right-click, or the menu key when it has the keyboard) has Rename…, Move to…, Delete… and Set as Main Document; an image's has Insert in Document.
  • Drag a file onto a folder to move it there.

Adding files, folders and zip files

File › Add Files… copies files into the project. You can also drop files on the window:

  • Files are added at the project's top level.
  • A folder is added with its files and its folders.
  • A zip file asks first: Unzip into the Project, Add the Zip as a File or Cancel. File › Import a Zip File… unzips without asking. When everything in a zip is inside one folder, that folder is left off the paths.

When files of the same name are there already, one question covers the whole drop: Replace, Keep Both (the new one gets another name, such as figure-2.png) or Skip.

Some things are always left out, and the status line says what and why: hidden files and folders (such as .git), the build's leftovers (.aux, .log, .synctex.gz, .toc…), links that point out of the folder, and names in a zip that would land outside the project. An import holds at most 5,000 files and 500 MB, and a zip that expands suspiciously far is refused whole.

On the start page, a dropped folder opens as a project Desktop only, and a zip file (or, in the browser, a folder) becomes a new project, which you then save where you choose.

History and versions

Every project has a history, and on the desktop that history is a git repository in the project's folder, whether or not it is ever pushed anywhere.

  • A folder that is not in a repository becomes one on its first save, and each save that changes something is a new version (a commit).
  • A folder already in a repository of its own is used as it is: saving does not commit. Use Commit… in the History section when you want a version, with your own message.
  • In the browser, each save that changes something is a version kept in the browser, with the same comparisons and restores.

The History section of the side panel lists the versions, newest first. Choose one to see what it changed in each file, line by line (What this commit changes). From there:

  • Restore This File… brings one file back as it was;
  • Restore the Project at This Version… brings back every file, and removes the files added since.

A restore comes back as unsaved changes: nothing is lost, and the next save makes a new version, so the history keeps every version, including the one you restored over.

Commits carry your git identity when your system has one (git config user.name and user.email), and the name TeXCraft otherwise. When TeXCraft makes the repository, it also writes a .gitignore that keeps build files out.

To keep the history on GitLab or GitHub too, see Push and pull and Save Project to GitHub or GitLab.

The .texcraft folder

TeXCraft keeps a few things of a project in a hidden .texcraft folder inside it, so they travel with the project and its history:

  • .texcraft/review/: the comments and suggestions, one file per thread (Comments and suggestions);
  • .texcraft/words.txt: the project's own spellings;
  • whether AI may be used in this project (AI assistance).

Projects in the browser

The browser version keeps projects in your browser's storage for this site, by name. The start page lists them under Projects in this browser, to open or to delete. The page asks before you leave it with unsaved changes.

Projects stay in this browser on this computer only. Clearing the site's data in the browser deletes them. To keep a copy elsewhere, save the project to GitLab or GitHub (how); exports and the PDF can be downloaded at any time.
