GitLab and GitHub

TeXCraft works with projects kept on GitLab or GitHub, including your organisation's own GitLab server or GitHub Enterprise Server. It talks to them directly: there is no TeXCraft server in between.

There are two ways to work with a repository:

  • Open a project from GitLab or GitHub, edit it, and commit back to its branch. This works on the desktop and in the browser, with nothing to set up.
  • Push and pull a project folder that is a git repository with a remote, as git does. Desktop only

Either way, Sync beside the project's name does it all in one click.

Not yet tried widely: pushing, pulling and saving a project to a new repository are new in 0.12.0 and have had little use against the real services yet. Keep a copy of important work, and please report what goes wrong.

Signing in

TeXCraft needs your permission to read a project, and to commit to it. You can sign in, or give a personal access token.

Sign In with GitLab
In the Open and Commit dialogs, or in Settings › Accounts. GitLab's page opens in your browser; once you let TeXCraft in, it is signed in. It asks only to read at first; the first commit asks once more, with Allow Commits on GitLab. On the desktop the sign-in is kept in your system's keychain, so a restart stays signed in; in the browser it lasts as long as the tab is open.
Sign In with GitHub Desktop only
The dialog shows a code, with Copy Code and Open GitHub's Page; enter the code on GitHub's page. In the browser, GitHub's sign-in does not answer web pages, so use a token there.
A personal access token
Choose Use a personal access token instead in the dialog, and paste the token in the Personal access token field. TeXCraft keeps a token only while it runs (in the browser, while the page is open) and never writes it anywhere.
  • GitLab: the read_api scope to open a project, api to commit or make a repository.
  • GitHub: a fine-grained token with access to the repository, with Contents read-only to open it, read and write to commit, and Pull requests read and write to open a pull request; Administration read and write to make a repository. A classic token needs the repo scope.

Sign Out, in Settings › Accounts, forgets the sign-in at once. On GitLab it also withdraws TeXCraft's access; on GitHub, remove TeXCraft under your GitHub account's settings, in the applications you have authorised.

Opening a project from GitLab or GitHub

File › Open from GitLab or GitHub… (also on the start page) asks for:

  • the Service: GitLab or GitHub, chosen by itself for addresses on gitlab.com and github.com;
  • the Project address: its web page or any page under it, its clone address, or just group/project. Once you are signed in, the projects you can reach are suggested as you type;
  • the Branch: a list of the project's branches, with the default branch chosen.

On the desktop the project opens in memory, linked to its branch, not in a folder: your changes go back with Commit, and TeXCraft asks before closing with changes not committed. (Save Project As… can still copy it into a folder.) In the browser it is kept with your browser's projects, with its link, so a reload keeps your changes.

The top bar shows the project, the branch and how many files you changed. Hidden files (such as .gitignore) stay on the branch as they are. Files over 10 MB are skipped, and said; a project over 200 MB is refused.

Committing

File › Commit to GitLab… (or Commit to GitHub…) lists the files you changed and asks for a message. Before committing, TeXCraft looks at the branch: commits others made in the meantime are taken in first, so nothing anyone committed is written over.

Keeping up with the branch

File › Update from GitLab (or GitHub) takes in what others committed. TeXCraft also checks by itself every two minutes, and when its window comes back to the front, quietly: what came in is said on the status line.

  • A file changed only on the branch is taken in.
  • A text file changed on both sides is merged line by line, when the changes are on different lines.
  • Changes to the same lines, a file deleted on one side and changed on the other, and binary files changed on both sides are conflicts: nothing is taken in until you choose, for each file, Keep mine or Take theirs. The top bar shows how many files are in conflict, and the next commit offers the same choices.

Comments and suggestions (review) are committed and updated with the project.

A new branch and a merge request

When you cannot commit to the branch (it is protected, or your role does not allow it), or you prefer not to, the commit dialog offers Commit to a new branch and open a merge request (on GitHub, a pull request). Your changes go to the new branch, the request is opened into the original branch, and its link is shown. The project then follows the new branch, so later commits add to the same request.

Sync

When a project has a remote (its folder's git remote, or the branch it was opened from), ⇅ Sync stands beside its name in the top bar, with what waits to go either way: ↑2 for two versions to send, ↓1 for one to receive (as last seen); hovering says it in words. One click:

  1. makes a version of your changes, if there are some (History);
  2. takes in the remote's new commits, merging text files changed on both sides line by line;
  3. sends your versions.

The status line says what came in and what went out. When the same lines changed on both sides, nothing is taken in yet: a dialog lists the files, and for each you choose Keep mine or Take theirs, then Sync again. When the server wants a token TeXCraft does not have, it asks for one; it keeps it only while it runs. Sync is also in the File menu.

For a project opened from GitLab or GitHub, Sync commits your changes to its branch with a message that says what changed (or, with no changes, takes in the branch). Commit to GitLab… stays there to write your own message.

Projects on Overleaf Desktop only

A project cloned from Overleaf with git has a remote such as https://git@git.overleaf.com/…. TeXCraft recognises it and shows the service's name, with a small cloud icon, beside Sync and in the History section. Sync works as with any git remote. Overleaf asks for a git authentication token: make one in your Overleaf account's settings, and paste it when TeXCraft asks.

Push and pull for project folders Desktop only

A project folder is a git repository (History). When it has a remote on GitLab, GitHub or another server, the History section shows it (the service's name when TeXCraft recognises it), with ↑ Push and ↓ Pull buttons and what waits to go either way (↑2 ↓1, in words on hover). They are also in All Commands (Ctrl+Shift+P).

Push
Makes a version of your changes, then sends the commits of the branch you are on. If the remote's branch has commits you do not have, the push is refused before anything is sent: pull first (or Sync). A refusal by the server (a protected branch, for example) is shown with its reason.
Pull
Makes a version of your changes, then takes in the remote's commits: a fast-forward when you have nothing new, or a merge when both sides have commits. Text files changed on both sides are merged line by line; when they cannot be, the pull is refused, naming the files, and nothing changes (Sync offers the choice of a side for each). A file changed on disk outside TeXCraft and not committed stops the pull too.

TeXCraft uses your sign-in or token for the remote's server, and asks for a token when it has none. It speaks git over HTTPS; an SSH address (git@gitlab.com:group/project.git) is reached over HTTPS at the same path.

Not yet: SSH itself, other branches than the one checked out, force pushes, and merging the two sides of a conflict inside a file (keep one side, or merge it with git). For those, use git alongside TeXCraft: the repository is an ordinary one.

Save Project to GitHub or GitLab

A project that is on no server yet can get a repository of its own: File › Save Project to GitLab or GitHub › Save Project to GitHub… or Save Project to GitLab… (also in the History section while the folder has no remote). The dialog asks for the server, the owner (you, or one of your organisations or groups), the name (suggested from the folder's), who can see it (Private, the default, or Public) and an optional description.

  • On the desktop, TeXCraft makes the repository, sets it as the folder's origin, and pushes the whole history. Unsaved changes are saved and committed first.
  • In the browser, the files go in as the repository's first commit (the versions kept in the browser stay there), and the project is then linked to it as if opened from it.

The dialog ends with Open in Browser for the repository's page.

Your organisation's servers

A company's or a university's GitLab, or a GitHub Enterprise Server, works as gitlab.com and github.com do, once TeXCraft is registered on it as an application, by you for yourself or by its administrator for everyone.

  1. In Settings › Accounts, choose Add a GitLab Server… or Add a GitHub Enterprise Server…, and type the server's address (any page on it will do). The Open dialog offers the same for a project on a server it does not know.
  2. TeXCraft checks that the server answers as GitLab or GitHub does, then shows what to register on it, each value with a Copy button, and a button opening the right page.
  3. Paste the Application ID (on GitHub, the Client ID) you get, and choose Add Server. Then sign in with its own Sign In button.

A link can propose a server too: https://texcraft-893d51.gitlab.io/?gitlab=https://git.example.org/group/project&client_id=…, in the browser, or the same address given to the desktop app when starting it. TeXCraft always asks before adding it.

In the browser, the server must accept requests from web pages; many do not. TeXCraft says so when it gets no answer, and the desktop app is then the way.

On the desktop, servers whose certificates come from your organisation's own certificate authority work when that authority is installed on the computer.

Servers provided by your organisation Desktop only

An administrator can give everyone the servers, ready to sign in to, with a file named texcraft-forges.toml. TeXCraft reads it at start from the system-wide folder, then from your settings folder (where); the first file to list a server wins.

The system-wide folder
SystemFolder
Linux and other Unix systems/etc/texcraft/
macOS/Library/Application Support/TeXCraft/
Windows%ProgramData%\TeXCraft\
 
[[server]]
address = "https://git.example.org"
service = "gitlab"     # or "github" for a GitHub Enterprise Server; gitlab when left out
client_id = "…"        # the application registered for everyone

These servers show as "Provided by your organisation." in Settings › Accounts and cannot be removed there. An entry TeXCraft cannot use is left out, and Settings › Accounts says why.
